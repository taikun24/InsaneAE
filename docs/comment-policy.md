# コメントの方針

このファイルは `main` (1.20.1) と `1.21.1` の両ブランチに同じ内容で置いてあります。
Java・Python・Gradle などのコメント (Javadoc を含む) は、次の基準で書きます。

## 残すコメント

コードを読んでも分からないことだけを書きます。

- 理由: なぜこの書き方なのか、なぜ別の素直な書き方ではいけないのか。
- 制約: 呼び出してよい時点、触ってはいけない状態、値の上限とその根拠 (int の上限、long の溢れなど)。
- ワークアラウンド: AE2 や他 Mod の仕様・不具合を避けるための処理と、避けている内容。
- 外から見えない前提: Mixin の注入先がどこか、反射で名前を引いている理由、他 Mod の挙動への依存。

## 消すコメント

- コードを読めば分かること (メソッド名・変数名の言い換え、処理をそのまま日本語にしたもの)。
- 変更履歴 (「以前は〜していた」「2026-07 に変更」「〜から移した」)。履歴は Git とコミットメッセージに書きます。
- 手順の実況 (「まず〜する」「次に〜」「ここで〜を取得」のように、処理の流れを読み上げるだけのもの)。

理由を説明する文の中に履歴が混ざっている場合は、理由だけを残して書き直します
(「以前は全枠を読み直していて遅かったので」ではなく「全枠を読み直すと 1620 枠で約 30ms かかるので」)。
issue 番号は、理由の出典として 1 つ添える程度なら残してかまいません。

## 書き方

- 日本語の文体は共通の執筆ルール (ja-style) に従います。比喩動詞 (効く・刺さる・踏む など)、
  英語の直訳、矢印や体言止めで文を詰めることは避けます。
- Javadoc の `<b>` は、読み飛ばされると事故になる注意点だけに付けます。
- コメントを消した結果、空になった区切り (`// ----`) や中身の無い Javadoc は残しません。
